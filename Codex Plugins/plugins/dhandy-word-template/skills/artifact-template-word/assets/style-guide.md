# 단디메카 Word 표준 포맷 가이드

> 적용 대상: 기술보고서, 설계 사양서, 수행계획서, URS, 검증·인수 문서<br>
> 포맷 버전: 1.12 / 2026.07.23<br>
> 기준 문서: `[단디메카] CURECA Prep v2.0 설계 사양 보고서_260420.docx`

## 1. 목적과 우선순위

이 가이드는 프로젝트와 작성자가 바뀌어도 단디메카 문서가 동일한 시각 체계와 편집 규칙을 유지하도록 한다. 판단 순서는 다음과 같다.

1. 정보 정확성과 추적성
2. 제목·본문·표의 계층 일관성
3. 제목과 메타데이터가 길어져도 깨지지 않는 안정성
4. 단디메카 브랜드 톤
5. 장식적 요소

## 2. 디자인 DNA

- 표지: 넓은 백색 여백, 좌측 30.7 mm 그라데이션 띠, 우측 정렬 정보 블록을 사용한다.
- 본문: 흑백 중심의 기술 문서로 구성하고 주황색은 중요 라벨과 제한된 강조에만 쓴다.
- 표: 연한 회색 머리행, 얇은 회색 선, 충분한 셀 여백을 기본으로 한다.
- 글 앞에 네모·막대 같은 장식 기호를 붙이지 않으며 장식용 구분선과 불투명 텍스트 박스는 사용하지 않는다.
- 문서 구조: 공문서의 문서관리·승인·개정 체계를 따르되, 기술문서의 넓은 표·도면 가독성을 우선한다.

## 3. 페이지와 구역

- 용지: A4 세로, 210 × 297 mm
- 본문 여백: 위 25 mm, 아래 25 mm, 왼쪽 10 mm, 오른쪽 10 mm
- 머리말·바닥글 거리: 각각 10 mm
- 문서는 `표지 구역`과 새 페이지에서 시작하는 `본문 구역`으로 나눈다. 두 구역은 동일한 A4 여백을 사용한다.
- 표지에는 머리말·바닥글을 노출하지 않는다.
- 본문은 `기본 머리말·바닥글` 한 쌍만 사용한다. 첫 페이지 및 홀수·짝수 구분은 비활성화하고 관련 관계를 만들지 않는다.
- 기본 순서는 `표지 → 문서 기본정보·승인·개정이력 → 목차 → 본문 → 부록`으로 한다.
- 1단계 제목은 명시적 페이지 나누기로 새 페이지에서 시작한다.

## 4. 표지 규칙

### 4.1 고정 구조

1. 좌측 그라데이션 띠: 폭 30.7 mm, 전체 높이
2. 로고: 약 57 mm 폭, 상단 70±4 mm 범위
3. 문서 유형 태그: 9.5 pt Bold, Dhandy Orange
4. 주제목: 약 165 mm 폭의 오른쪽 정렬 영역, 1줄 우선
5. 부제: 주제목과 동일한 약 165 mm 폭, 오른쪽 정렬, 1줄 우선
6. 고객명: 주제목과 동일한 약 165 mm 폭, 오른쪽 정렬, 1줄 우선
7. 문서 정보: 약 63.5 mm 폭, 오른쪽 끝선 정렬, 마지막 줄의 하단 여백 40±3 mm

로고, 문서 유형, 주제목, 부제, 고객명, 문서 정보의 시각적 오른쪽 끝선은 재단선에서 10±0.5 mm 지점의 하나의 축으로 맞춘다.

### 4.2 입력 길이 대응

| 항목 | 규칙 |
|---|---|
| 주제목 18자 이하 | 28 pt, 1줄 우선 |
| 19~23자 | 26 pt, 1줄 우선 |
| 24~27자 | 22 pt, 1줄 우선 |
| 28~31자 | 20 pt, 1줄 우선 |
| 31자 초과 | 표지용 축약 제목을 별도 작성; 20 pt 미만 축소 금지 |
| 부제 | 13.5 pt 기본, 1줄 우선; 필요 시 13 pt까지 |
| 고객명 | 11.5 pt, 1줄 우선 |
| 메타데이터 라벨·값 | 10 pt, 기본 2줄; 문서번호만 3줄 허용 |

- `URS`, `FAT` 같은 8자 미만 약칭을 주제목으로 단독 사용하지 않는다.
- 약칭만 입력된 경우 `장비 개발 사용자 요구사항 사양서`처럼 설명형 제목으로 보완하고 약칭은 문서 유형 또는 부제에 둔다.
- 제목이 길어져도 로고와 문서 정보의 기준 위치는 바꾸지 않는다. 165 mm 영역과 규정 글자 크기로 1줄 유지가 어려우면 문구를 축약한다.
- 주제목·부제·고객명은 약 165 mm의 공통 영역을 사용해 표지 흰색 영역 대부분을 활용하고 오른쪽 끝선을 고정한다.
- 주제목·부제·고객명에는 수동 줄바꿈을 넣지 않는다. 규정된 최소 글자 크기에서도 한 줄에 들어오지 않는 경우에만 문구를 축약하고, 전체 명칭은 문서 기본정보 표에 기록한다.
- 표지 주제목은 0.80배, 부제·고객명은 1.00배 행간을 사용한다. 표지 요소의 위치와 문단 앞·뒤 간격은 변경하지 않는다.
- 문서 정보는 작성일, 작성자, 문서번호, 버전을 기본으로 하고 최대 6개 항목만 표지에 둔다. 초과 항목은 본문의 문서 관리 표로 옮긴다.

### 4.3 표지 금지 사항

- 시작 위치가 일정하지 않은 부동 텍스트 박스
- 제목 입력량에 따라 로고가 상하로 이동하는 배치
- 표지 메타데이터 7개 이상
- 임의 줄바꿈으로 제목 모양을 맞추는 편집
- 글자 너비 축소, 장평 변경, 20 pt 미만의 주제목

### 5.1 문단 작성 규칙

- 한 문단은 하나의 주제만 다루고 원칙적으로 3~6문장, 8줄 이내로 유지한다.
- 의미 단위가 바뀌는 지점에서만 문단을 나눈다.
- 영문 약어는 처음 나올 때 한글 명칭과 함께 표기한다.
- Heading 1 바로 아래의 대분류 설명문은 Dhandy Body L1(11 pt Regular)을 기본으로 하며 문단 전체를 Bold로 처리하지 않는다.
- Dhandy Lead도 Regular를 유지하며 승인 결과나 핵심 결론처럼 한 문장만 별도로 강조할 때 선택적으로 사용한다.
- 원인·근거·맥락·예외처럼 문장 사이의 논리 관계를 설명할 때는 본문을 사용한다.
- 서로 비교하지 않는 병렬 항목이 3~7개이면 목록을 사용한다.
- 2개 이상의 공통 속성을 행별로 반복 비교하거나 ID·상태·담당·일자·검증 결과를 추적해야 하면 표를 사용한다.
- URS 요구사항, Open Item, 승인·개정 이력은 추적성을 위해 표로 작성한다.
- 한 문단을 둘러싸거나 위치만 맞추기 위한 1행 1열 표는 사용하지 않는다. 단, 7.3의 독립 강조박스는 유일한 예외로 한다.
- 본문은 첫 줄 들여쓰기를 사용하지 않는 블록형 문단으로 작성한다.
- 빈 문단이나 반복 Enter로 간격을 만들지 않고 문단 스타일의 앞·뒤 간격을 사용한다. 단, 일반 표 바로 뒤에 강조박스가 이어지는 경우에는 `Dhandy Callout Spacer` 빈 한 줄을 정확히 1개 넣는다.
- 행간은 본문·목록 1.14배, 제목 1.00배, 표·캡션 1.05배, 목차 1.08배를 기준으로 한다. 표지 주제목은 0.80배를 사용한다. 목차 문단 뒤 간격은 TOC 1/2/3에 각각 7/4/3 pt를 적용한다. 목차 항목이 25개 이상이고 1~2개 항목만 다음 페이지로 넘어가는 경우에 한해 3/1.5/1 pt까지 줄일 수 있으나 1.08배 행간과 글자 크기는 유지한다.
- 일반 본문, 수준별 본문, 글머리표 목록과 번호 목록은 모두 1.14배 행간, 문단 앞 0 pt, 문단 뒤 6 pt를 사용한다. 목록만 더 촘촘하게 보이도록 별도의 뒤 간격을 줄이지 않는다.
- 목록 항목은 문장형 또는 명사형 중 하나로 통일하고, 문장형에는 마침표를 사용한다.

### 5.2 제목과 하위 콘텐츠 정렬

제목과 문단은 계층 기준선을 사용하고, 표·그림은 별도의 개체 기준선을 사용한다. 강조박스는 왼쪽 바깥 들여쓰기 없이 전체 콘텐츠 폭을 사용한다.

| 수준 | 번호 시작 | 제목·하위 콘텐츠 시작 | 적용 스타일 |
|---|---:|---:|---|
| L1 | 0 mm | 8 mm | Heading 1 + Dhandy Body L1(기본) / Dhandy Lead(선택) |
| L2 | 8 mm | 16 mm | Heading 2 + Dhandy Body L2 / L2 목록 |
| L3 | 16 mm | 26 mm | Heading 3 + Dhandy Body L3 / L3 목록 |

- `2.1.1` 아래의 설명 문단에 Normal을 사용하지 않는다. 반드시 Dhandy Body L3를 사용해 제목 텍스트 시작선에 맞춘다.
- 일반 표·그림은 제목 수준과 관계없이 페이지 본문 왼쪽에서 8 mm 지점에 맞춘다. 강조박스는 왼쪽 0 mm에 맞춘다.
- 열이 많거나 폭이 중요한 표는 표 외곽선 기준 120 DXA(약 2.1 mm), 공정도·장비 배치도는 0 mm 전체 콘텐츠 폭을 사용한다.
- 표 캡션은 표의 왼쪽 끝과, 그림 캡션은 그림이 배치된 콘텐츠 영역의 가운데와 맞춘다.
- 들여쓰기는 Tab·공백·수기 번호가 아니라 지정된 Word 스타일과 실제 표 들여쓰기 값으로 구현한다.

## 6. 번호와 목록

- 제목: `1.` → `1.1` → `1.1.1`의 3수준만 사용한다. Heading 1에는 번호 뒤 마침표를 표시하고 Heading 2·3에는 단계 구분점만 사용한다.
- Heading 4 이하가 필요한 경우 제목 추가 대신 굵은 본문 또는 표로 재구성한다.
- 본문 목록은 최대 2단계까지만 사용한다. 3단계가 필요하면 소제목 또는 표로 재구성한다.
- 병렬 항목은 작은 원형 Word 자동 불릿, 순서가 필요한 절차는 Word 자동 번호를 쓴다.
- `●`, `-`, `1)` 등을 글자로 직접 입력해 목록을 만들지 않는다.
- 목차는 Heading 1~3 스타일에서 생성한 Word TOC 필드를 사용한다.

### 6.1 들여쓰기 기준

모든 값은 페이지 본문 영역의 왼쪽 기준선에서 잰다. 표식 뒤에서 줄이 바뀌면 두 번째 줄부터 `본문 시작` 위치에 맞춘다.

| 목록 수준 | 자동 표식 | 표식 위치 | 본문 시작 | 내어쓰기 | 글자 크기 |
|---|---|---:|---:|---:|---:|
| Bullet 1 | `•` | 3 mm | 7 mm | 4 mm | 본문 11 pt / 표식 8.5 pt |
| Bullet 2 | `◦` | 10 mm | 14 mm | 4 mm | 본문 11 pt / 표식 8.5 pt |
| Number 1 | `1.` | 0 mm | 9 mm | 9 mm | 11 pt |
| Number 2 | `1.1` 또는 `a.` | 7 mm | 16 mm | 9 mm | 11 pt |

- 불릿 표식은 `•`와 `◦`를 문장에 직접 입력하는 방식이 아니라 Word 목록 정의에 등록해 사용한다.
- Bullet 1의 표식은 8.5 pt로 작게 유지해 본문 11 pt보다 시각적 무게가 앞서지 않게 한다.
- 같은 수준의 항목은 동일한 문단 스타일을 사용하고 Tab·공백으로 들여쓰기를 맞추지 않는다.
- Number 2는 절차의 하위 순서에는 `1.1`, 선택지·조건의 하위 구분에는 `a.`를 사용하며 한 목록 안에서 혼용하지 않는다.
- 제목 소속 목록은 `Dhandy Bullet L1/L2/L3` 또는 `Dhandy Numbered L1/L2/L3`를 사용한다.
- 각 소속 목록의 표식은 해당 본문 기준선에서 3 mm, 목록 본문은 7 mm 안쪽에 둔다. 번호 목록은 해당 본문 기준선에서 시작하고 본문은 9 mm 안쪽에 둔다.
- 목록은 최대 2단계까지만 사용하고, 그보다 깊어지면 소제목·표·별도 요구사항으로 재구성한다.

## 7. 표, 그림, 주의 문구

### 7.1 표

- 본문 표의 전체 너비는 페이지 본문 폭을 넘지 않는다.
- 일반 표는 8 mm 개체 기준선에서 시작해 오른쪽 여백까지 사용한다.
- 열이 많거나 도면 수준의 폭이 필요한 대형 표는 전체 콘텐츠 폭을 사용하되 표 외곽선 들여쓰기를 120 DXA로 명시한다.
- 열 너비는 고정값으로 설정하고 AutoFit을 끈다.
- 행 높이는 `최소` 또는 자동을 쓰고 `정확히` 고정하지 않는다.
- 데이터 표의 머리행은 연한 회색 배경과 9 pt Bold를 쓰고 다음 페이지에서 반복한다.
- 데이터 표의 머리행과 본문은 각각 `Dhandy Table Header`, `Dhandy Table Body` 스타일을 적용하고 모두 9 pt로 고정한다. 표지·머리말·바닥글·문서정보·강조박스처럼 배치를 위한 표는 데이터 표로 보지 않으며 전용 스타일을 유지한다.
- 설명 열은 왼쪽, 코드·수량·상태·중요도는 가운데 정렬을 우선한다.
- 셀 내에서 줄바꿈하고 행 높이가 자동으로 늘어나게 한다.
- ID·코드·문서번호·개정번호 열은 예외적으로 줄바꿈 금지 속성을 적용한다. 해당 열은 가장 긴 값과 좌우 셀 여백이 한 줄에 들어오도록 고정 폭을 지정하고, `URS-01-001`·`OI-001` 같은 추적 ID 열은 최소 1800 DXA(약 31.8 mm)를 확보한다.
- ID 문자열 안에 수동 줄바꿈을 넣지 않는다. 폭이 부족하면 설명 열 등 비식별 열의 폭을 먼저 조정하고, 그래도 부족하면 표 분할 또는 가로 페이지를 사용한다.
- 표 바로 위에 `표 N. 제목`을 둔다.
- 일반 표는 실제 표 들여쓰기 454 DXA(8 mm)와 Dhandy Table Caption의 왼쪽 들여쓰기를 동일하게 설정한다.
- 대형 표는 실제 표 들여쓰기 120 DXA와 Dhandy Table Caption Wide의 왼쪽 들여쓰기를 동일하게 설정한다.
- 캡션 첫 글자의 시작선과 표 외곽 왼쪽 테두리는 정확히 같은 기준선에 있어야 하며 Tab·공백·셀 여백으로 맞추지 않는다.
- 외곽선은 0.75 pt, 내부선은 0.5 pt 이하의 회색으로 설정한다.
- 데이터 표 내부 글자는 9 pt를 사용하며 이보다 작게 줄이지 않는다. 공간이 부족하면 열 너비 조정, 허용 열의 줄바꿈, 표 분할, 가로 페이지 순으로 해결한다.
- 단위는 열 제목에 `분주량 (g)`, `온도 (°C)`처럼 표시한다.

### 7.2 그림과 도면

- 본문 폭을 넘지 않도록 크기를 제한한다.
- 일반 그림은 8 mm 개체 기준선의 콘텐츠 영역에서 가운데 정렬한다.
- 공정도·장비 배치도처럼 폭이 중요한 그림은 전체 콘텐츠 폭을 사용할 수 있다.
- 캡션은 그림 바로 아래에 `그림 N. 제목`으로 둔다.
- 100% 화면에서 세부 글자가 읽히지 않으면 원본 크기 그림을 부록으로 분리한다.
- 스크린샷은 필요한 영역만 자르고 중요 표시를 최소화한다.
- 저해상도 이미지를 임의 확대하지 않고, 가능하면 300 dpi 원본 또는 벡터 이미지를 사용한다.

### 7.3 주의·완료 기준 박스

- 독립된 1행 1열 표의 셀 전체를 Pale Orange로 채우고 왼쪽에 가는 Dhandy Orange 세로선을 사용해 예전처럼 밀도 있는 강조 면을 만든다.
- 제목 수준과 관계없이 왼쪽 0 mm 기준선에 배치하여 바깥 들여쓰기를 두지 않고 전체 콘텐츠 폭을 사용한다.
- `중요`, `주의`, `완료 기준`의 라벨만 주황색 Bold로 표시한다.
- 한 박스에 하나의 메시지만 넣고 4줄을 넘기지 않는다.
- 강조박스는 일반 데이터 표와 완전히 분리된 독립 1셀 표 구성요소로 작성한다. 일반 표 안에 중첩하거나 일반 표의 행·셀로 병합하지 않는다.
- 바로 앞의 최상위 개체가 일반 표일 때만 두 개체 사이에 `Dhandy Callout Spacer` 빈 한 줄을 정확히 1개 둔다. 앞 개체가 본문·목록·제목이면 별도의 상단 여백이나 빈 문단을 추가하지 않는다.
- 강조박스 내부 문단은 `Dhandy Callout`을 사용하고 셀의 상하 안쪽 여백으로 밀도를 조절한다. 반복 Enter나 수기 공백으로 높이를 만들지 않는다.
- 연속된 강조박스는 사용하지 않는다. 메시지가 여러 개이면 본문 또는 목록으로 분리하고 핵심 한 건만 박스로 남긴다.
- 주황색 세로선은 실제 출력 디자인이며, 편집 화면에만 나타나는 검은 네모 표식과 구분한다.

### 7.4 상태 색상

- 상태 텍스트는 반드시 표기하고 색상만으로 상태를 전달하지 않는다.
- `확정`은 Pale Green(`#E2F0D9`), `잠정`·`시험 중`은 Pale Yellow(`#FFF2CC`), `미결`·`협의 필요`·`시험 후 확정`은 Pale Orange(`#FFF2EC`) 배경을 사용한다.
- 상태 열 이외의 일반 본문·설명 셀에는 상태 색상을 확장하지 않는다. `필수·권장·선택` 중요도는 별도 요청이 없는 한 무채색으로 유지한다.
- 상태 색상은 한 문서에서 동일한 의미로만 사용하고, 진한 원색·빨강·녹색 글자색은 사용하지 않는다.

### 7.5 글 앞 장식

- 머리말의 영문 워드마크 앞에 붙던 주황색 네모(`■`)는 사용하지 않는다.
- Dhandy Lead에는 장식 막대를 사용하지 않는다. 주의·완료 기준 박스에는 규정된 가는 주황색 세로선만 허용한다.
- 강조가 필요하면 Pale Orange 배경과 `중요`, `주의`, `완료 기준` 라벨만 사용한다.
- 네모, 큰 원, 화살표 같은 문자 기호를 문장 앞에 수기로 붙여 시각적 계층을 만들지 않는다.

### 7.6 Word 편집 표식

- 제목이나 캡션 왼쪽에 보이는 작은 검은 네모는 글머리 기호가 아니라 `다음 문단과 함께`, `단락 나누지 않음`, `페이지 나누기 전에` 옵션을 나타내는 Word 비인쇄 표식이다.
- 표준 제목·캡션 스타일에는 위 자동 페이지 제어 옵션을 넣지 않는다. 대단원 새 페이지 시작은 문서 흐름에서 명시적 페이지 나누기로 처리한다.
- 제목 왼쪽의 접기·펼치기 삼각형은 Heading 스타일의 탐색 기능이며 인쇄되지 않는다. 제목 의미와 목차 기능을 유지하기 위해 Heading 1~3은 보존한다.

## 8. 머리말·바닥글과 필드

- 머리말 왼쪽: 표지 제목과 별도로 관리하는 축약 문서명, 9 pt
- 머리말 가운데: 축약 문서번호와 버전, 9 pt, 한 줄 유지
- 머리말 오른쪽: 별도 네모 표식 없이 영문 워드마크만 사용, 9 pt
- 바닥글 왼쪽: 배포구분 또는 보안등급, 9 pt
- 바닥글 가운데: `DHANDY MECHA`, 9 pt
- 바닥글 오른쪽: Word `PAGE / NUMPAGES` 필드, 9 pt
- 제목 상단과 페이지 바닥에는 각각 0.5 pt 흑색 구분선을 사용한다.
- 목차, 페이지 번호, 참조 번호는 일반 텍스트가 아닌 Word 필드로 작성한다.
- 배포 전 `Ctrl+A → F9`로 필드를 갱신한 뒤 페이지 번호와 목차를 확인한다.

### 8.1 공식문서 표기

- 날짜는 `2026. 7. 22.`, 기간은 `2026. 7. 22.~2026. 8. 31.` 형식으로 쓴다.
- 수치와 단위는 `2 g`, `100 mL`, `25 °C`처럼 한 칸 띄고, 범위는 `2~5 g`으로 쓴다.
- 요구사항은 `~하여야 한다`, 설명·현황은 `~한다` 또는 `~이다`로 문체를 통일한다.
- 미정 사항은 `미정`, `협의 필요`, `추후 확정` 중 하나로 표시한다.
- 승인권자의 검토·승인을 거쳐 설계 기준이 공식 결정된 상태는 `설계 확정`으로 표기한다.
- `설계 동결`, `Fix`, `Freeze`처럼 승인 여부가 불명확한 표현은 설계 확정의 동의어로 사용하지 않는다.
- 영문 약어는 최초 사용 시 한글 또는 영문 원문과 함께 표기한다.

### 8.2 글꼴 포함과 외부 편집

- 고객 제출용 DOCX에는 Pretendard Regular와 Bold 계열의 전체 글꼴을 포함한다.
- `파일에 글꼴 포함`을 활성화하고 `문서에 사용된 문자만 포함`은 비활성화한다. 부분 글꼴은 새로운 문자 입력에 제약이 있으므로 편집용 문서에 사용하지 않는다.
- 저장 후 `word/fonts` 글꼴 파트, `fontTable.xml` 포함 관계, `embedTrueTypeFonts=true`, `saveSubsetFonts=false`를 구조적으로 확인한다.
- 다른 편집기에서 다시 저장하면 내장 글꼴이 제거될 수 있으므로 최종 배포 전 글꼴 포함 검사를 다시 수행한다.
- 웹 오피스보다 Microsoft Word 데스크톱에서 편집하는 것을 기본으로 한다.

## 9. URS 문서에 적용하는 방법

| URS 내용 | 권장 형식 |
|---|---|
| 문서 목적·범위 | Heading 1 + Dhandy Body L1/L2, 핵심 결론만 Dhandy Lead 선택 |
| 용어·약어 | 항목이 적으면 목록, 반복 속성이 있으면 2~3열 표 |
| 시스템 구성·공정 흐름 | 그림 + 캡션 + 본문 설명 |
| 개별 사용자 요구사항 | `ID / 사용자 요구사항 / 중요도 / 검증 방법` 표 |
| 성능·안전·유지보수 | Heading 2 단위 구분 + 요구사항 표 |
| 제외·미정·고객 확인 항목 | 주의 박스 또는 Open Item 표 |
| FAT·SAT·인수 기준 | 요구사항 ID와 연계된 검증 표 |
| 개정 이력 | `Rev. / 일자 / 작성·검토 / 변경 내용` 표 |

### 9.1 요구사항과 Open Item ID

- 사용자 요구사항 ID는 `URS-[2자리 숫자 분류]-[3자리 일련번호]` 형식으로 부여한다. 예: `URS-01-001`, `URS-02-001`, `URS-08-001`.
- 숫자 분류는 문서 시작부에 정의한다. 기본 권장 분류는 `01` 공통, `02` 분주, `03` 혼합, `04` 건조, `05` 회수·이송, `06` 분석장비 연계, `07` 제어·데이터, `08` 안전·오염관리, `09` 유지보수, `10` 검증·인수이다.
- 일련번호는 분류별로 `001`부터 독립 부여한다. 분류가 달라도 전체 형식과 자리수는 동일하게 유지한다.
- 미정·협의 필요·고객 확인 항목은 `OI-001`부터 3자리 일련번호로 부여한다.
- ID는 문서 개정 후에도 유지하며 삭제된 번호를 재사용하거나 승인 이후 일괄 재번호하지 않는다.
- Open Item이 요구사항에 영향을 주면 `OI-001 → URS-02-001`처럼 상호 참조하고 확정 결과를 개정 이력에 남긴다.
- 프로젝트명·고객명은 요구사항 ID에 넣지 않는다. 신규 숫자 분류가 필요하면 기존 번호와 중복되지 않게 문서 시작부에 먼저 정의한다. 고객 규정이 있으면 고객 규정을 우선한다.
- 요구사항·Open Item ID 열은 `줄 바꿈 안 함`으로 설정하고 최소 1800 DXA 폭을 확보한다. ID가 두 줄로 보이면 글자를 줄이거나 문자열을 분리하지 말고 열 폭과 전체 표 구성을 조정한다.

## 10. 금지 사항

- 스타일 대신 개별 글자에 크기·색·리딩을 직접 지정하는 편집
- 자동 번호 대신 수기로 제목 번호를 작성하는 편집
- `●`, `-`, `1)` 같은 문자를 수기로 입력한 목록
- 머리말 워드마크와 Lead 문단 앞의 네모·막대 장식 또는 규정 외의 주의 박스 장식
- Heading 2·3 아래에서 Normal을 사용해 하위 콘텐츠가 최상위 왼쪽 기준선으로 되돌아가는 편집
- Heading 2·3의 들여쓰기를 표·그림에 그대로 누적해 개체 폭을 불필요하게 줄이는 편집
- 고정 행 높이 때문에 긴 텍스트가 잘리는 표
- 머리행이 반복되지 않는 다중 페이지 표
- 데이터 표에서 9 pt가 아닌 머리행·본문 글자를 사용하거나 ID·코드·문서번호류를 두 줄로 나누는 편집
- 표지와 페이지 장식에 인라인 공백을 반복 입력해 위치를 맞추는 방식
- 프로젝트 내용 변경 때마다 로고·색·포함 여백을 임의로 바꾸는 편집
- 편집용 고객 제출본을 부분 글꼴 포함 또는 글꼴 미포함 상태로 저장하는 방식

- 고객명 1줄
- 작성자 1줄 / 2줄
- 문서번호 1줄 / 3줄
- 버전 1줄 / 2줄

합격 조건: 주제목·부제·고객명이 각각 165 mm 영역에서 1줄을 유지하고, 문서 정보 최대 6항목에서 겹침·잘림·로고 이동이 없어야 한다. 범위를 넘는 입력은 글자 크기를 추가 축소하거나 줄바꿈하지 않고 표지용 문구를 축약한다.

### 11.2 구조 검사

- A4, 여백, 구역, 머리말·바닥글 거리
- Heading 1~3 스타일과 다단계 번호
- TOC·PAGE 필드
- 모든 표의 고정 열 너비, 자동 행 높이, 반복 머리행
- 데이터 표의 `Dhandy Table Header`·`Dhandy Table Body` 9 pt 적용
- ID·코드·문서번호·개정번호 열의 고정 폭, 줄바꿈 금지, 수동 줄바꿈 없음
- Normal·Dhandy Body·글머리표·번호 목록 스타일의 1.14배 행간, 앞 0 pt, 뒤 6 pt 일치
- 일반 표·캡션의 454 DXA 기준선, 대형 표·캡션의 120 DXA 기준선, 대형 그림과 강조박스의 0 mm 기준선
- 목차 1.08배 행간과 TOC 수준별 문단 뒤 간격
- 표지 주제목의 0.80배 행간
- Dhandy Callout의 독립 1셀 표 구조, Pale Orange 전체 채움, 주황색 왼쪽 선, 일반 표 뒤 조건부 한 줄 간격 및 상태 셀 색상 매핑
- 그림 내용 설명과 캡션
- Pretendard 전체 글꼴 파트와 포함 관계
- 불필요한 직접 글자·문단 서식의 최소화

### 11.3 렌더 검사

- Word에서 필드를 갱신하고 PDF로 변환한다.
- 전 페이지를 이미지로 렌더링해 잘림, 겹침, 글꼴 대체, 비정상 공백, 빈 페이지를 확인한다.
- 머리말, 바닥글, 페이지 번호가 모든 본문 페이지에서 동일한지 확인한다.
- 외부 편집을 가정해 새 한글 입력이 가능한 전체 글꼴 포함 상태인지 확인한다.
- 문서 파일 구조 검사와 전 페이지 시각 검사를 둘 다 통과한 파일만 배포한다.

### 11.4 자동 QA

- 최종 저장 후 `python scripts/qa_word_template.py "<결과.docx>"`를 실행한다.
- ID·코드 표가 있어야 하는 기준본·URS·요구사항 문서는 `--require-id-column` 옵션을 추가한다.
- 검사는 본문·목록 간격 일치, 데이터 표 9 pt, 고정 열 구조, ID 열 최소 폭과 줄바꿈 금지, 내장 글꼴 설정을 확인한다.
- 자동 QA 실패 항목을 수정한 뒤 다시 검사하고, 자동 QA와 전 페이지 렌더 검사를 모두 통과한 파일만 배포한다.
